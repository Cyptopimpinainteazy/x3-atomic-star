# Lane: BTC header source + relayer (TICKET-095, registry row `btc_fortress_gateway`)

Registry row: `btc_fortress_gateway`, currently **45%**, `crate_or_service = pallets/x3-settlement-engine`.

## The blocker you are attacking

> "No live Bitcoin run beyond regtest … the header still arrives by an operator copying a hash —
> there is no header source and no peer-sourced sync"

The design is already written: `.ai/reports/btc-header-source-design-20260922.md` (88 lines, read it
first). The pallet half of that design **already exists**:

* `BtcHeaderSubmitter` (`pallets/x3-settlement-engine/src/lib.rs:228`)
* `submit_btc_headers(origin, headers: Vec<BtcBlockHeader>)` (`lib.rs:2037`)
* tests for both (`src/tests.rs:4670`)

What does not exist: anything that *fetches* headers from a real source, checks that they link, and
turns them into the call's encoding. `submit_btc_header` (singular) is still root-only, the repo has
no Bitcoin client, and nothing watches Bitcoin.

## Deliverable

1. `scripts/btc/push-headers.py` — a real header source + relayer, default OFF (never runs unless the
   operator names a source):
   * source A: a public Esplora-style HTTP endpoint (`--esplora https://blockstream.info/testnet/api`
     or a self-hosted one). Use `/block-height/<h>`, `/block/<hash>/header` (hex).
   * source B: a local `bitcoin-cli` when `X3_BITCOIND_DIR` is set (reuse the patterns in
     `scripts/btc/capture-regtest-spv.py`).
   * It must check, locally and before emitting anything: parent link (`prev_blockhash` of header
     *k+1* == hash of header *k*), the source's own answer for the hash at each height, and no gap.
     Stop loudly on the first disagreement. `--cursor <file>` keeps the last pushed height/hash.
   * It emits the `submitBtcHeaders` call **encoding** plus the height/hash it reached, and refuses
     to emit a batch whose headers are not a single linked run.
   * It must not need a signer to be useful or testable. If a signing path is reachable cheaply
     (`npm ci` in `packages/ts-sdk`, or a small `subxt` binary), adding it is a bonus — but do NOT
     let it become the deliverable. Say plainly in the script header what it does and does not do.
2. `scripts/testnet/btc-header-source-drill.sh` (+ `.py` if useful) — a live drill that:
   * runs the fetcher against a **real public testnet endpoint** (network is enabled on this box),
     prints the chain it verified (height, hash, link check), and
   * proves refusal: a deliberately broken run (gap, tampered parent, or a header the source
     disagrees with) must fail with a non-zero exit and a message naming the height.
3. A Rust test (in `pallets/x3-settlement-engine/src/tests.rs`, next to the existing
   `submit_btc_headers` tests) that takes the **bytes the script produced** — checked in under
   `pallets/x3-settlement-engine/src/tests/data/` or generated by the drill into a path the test
   reads — decodes them with the pallet's own `BtcBlockHeader`, and asserts the batch is admitted in
   order on an anchored test chain. This is the link that makes the script evidence rather than a
   script that prints JSON: the pallet must decode and accept what the relayer emits.

## Hard rules (same as AGENTS.md)

* No fake data in the product path. If a public endpoint is unreachable, the drill **fails or skips
  loudly** — it never substitutes a canned header set and calls it live.
* Never weaken/delete/skip a test or gate. Break-it-first: remove your own check → red → restore
  byte-identically → green.
* Do not edit `scripts/local-ci.sh` while a `local-ci.sh` run is executing, and never `git add -A`
  (other lanes share this tree). Carve explicit paths.
* The registry row is scored with `implemented*0.35 + tested*0.25 + mainnet_ready*0.40`; say the three
  numbers in the comment. `mainnet_ready` stays low without a public-network run.

## Proof required before you report done

* `bash scripts/testnet/btc-header-source-drill.sh` — PASS, with the real heights/hashes it verified.
* The pallet test that decodes the emitted payload — green, and red when you break the linkage check.
* `cargo test -p pallet-x3-settlement-engine` (or the crate's real name) green; `cargo fmt` clean.
* `python3 scripts/x3_audit_matrix.py && python3 scripts/x3_audit_matrix.py --check` after any
  registry edit.
